A three-stop reference route

  1. Input and orchestration: open src/app.js and search for chooseFile, then analyzeLocal. The file stays local through a browser object URL. Each run owns an abort controller so cancellation and source replacement cannot finish an obsolete report.
  2. Sampling and the decision: open src/video.js at sampleVideo, then src/analyze.js at analyzeFrame and flagsFor. Sequential seeking supplies real decoded pixels. Three measurements feed explicit thresholds; a low-detail flag is only a prompt for review.
  3. Visible evidence and export: return to showSample in src/app.js. It draws the measured sample and seeks the original clip. src/export.js, at createReport, lists exactly which fields may leave the app in a report.

A practice to reuse

The requirements distinguish a generated demo from decoding a real video file. The pixel tests in tests/analyze.test.mjs establish the measurement logic; the separate recorded WebM fixture exercises decoding through the actual chooser. These are different claims and need different evidence. On another project, define the visible outcome and its integration boundary before deciding which test proves it.

Run it again

From the project directory, with Node.js 20 or newer:

node serve.mjs
# Open http://127.0.0.1:8791/

node --test tests/analyze.test.mjs tests/export.test.mjs tests/video.test.mjs

No dependency installation or account is needed. Stop the server with Ctrl+C. This map works as a local HTML file without scripts or a network connection; source links are relative to the repository.
